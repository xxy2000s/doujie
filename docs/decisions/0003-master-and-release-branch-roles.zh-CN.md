# ADR-0003：master 是开发主线，release 是部署指针

状态：已接受
日期：2026-08-02

## 背景

服务端需要可审计的部署引用，但没有必要维护第二份被删减的源码。为了“部署精简”而从 release 删除文档或开发文件，只会制造分支冲突，也不会影响最终构建出的 `dist/`。

## 决策

- `master` 是完整开发主线；
- `release` 指向获准部署到服务器的准确 commit；
- 服务器拉取并检出 `release`，然后安装、验证、构建和重启服务；
- 文档保留在两个分支，部署消费构建产物，而不是人工删减的源码树；
- 每次推送远程都需要用户针对该次操作明确授权。

## 后果

- 发布通常是把 `release` 推进到已经验证的 `master` commit；
- 回滚选择历史已验证 commit，重新构建，不删除运行数据；
- 不假设两个分支永远相等，每次部署前都要检查；
- 远程当前状态属于运行数据，应实时查询，不作为永久事实写入文档。

## 未采用方案

- 维护只含代码的 release 分支：增加漂移和冲突，不能降低运行风险；
- 从任意工作树直接部署：缺少审计和可靠回滚能力。
