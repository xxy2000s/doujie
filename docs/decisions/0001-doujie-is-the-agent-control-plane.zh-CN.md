# ADR-0001：豆姐是 Agent 控制面

状态：已接受
日期：2026-08-02

## 背景

豆姐最初具备飞书到本地 AI 的桥接能力，但目标产品是用户用于监督和协调多个项目 Agent 的数字员工。如果把每个飞书会话直接当作项目工作区，会让控制面耦合任意项目目录，并模糊管理权限边界。

## 决策

豆姐是面向操作者的数字员工、飞书入口和 Agent 控制面。她自己的默认工作区是豆姐仓库。具体项目工作交给具有独立 provider、原生 Session ID、cwd、别名和权限的项目 Agent。

豆姐不是某个项目的专用编码 Agent，也不是旧 InfoHunter 产品的延续。

## 后果

- 飞书群表示管控会话，不隐式表示项目目录；
- 项目工作必须通过明确的 registry 元数据调度；
- 豆姐负责路由、权限、可观测性、恢复和审计；
- 项目 Agent 负责其注册工作区内的实现；
- 项目文档和命名应始终把豆姐描述为数字员工和控制面。

## 未采用方案

- 每个群直接绑定项目 cwd：初期简单，但不适合作为统一控制员工；
- 让豆姐直接修改所有目标项目：会取消管理与执行之间的重要边界。
